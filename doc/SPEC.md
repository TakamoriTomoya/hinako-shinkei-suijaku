# ひなこの神経衰弱 - MVP仕様

## コンセプト
「ひなこタワーバトル」と同じひなこの写真を使い、りんご柄の背景で遊ぶ、トランプの神経衰弱。

## 対象プラットフォーム
- Web(PC / スマホブラウザ)。縦長のスマホ画面を基準にレイアウトする

## ゲームルール
1. ホームで選んだ枚数(16枚=8種類 / 24枚=12種類)のカードを裏向きにランダムに並べる。絵柄は画像一覧からランダムに選ぶ。
   オンライン対戦ではホスト(先に入った人)が選んだ枚数になる。24枚は縦長の画面では4列×6行、横長では6列×4行で並べ、上下の帯を細くして盤面を広く取る
2. 1回に2枚めくる。同じひなこならそろったカードとして表のまま残り、同じ人がもう一度めくれる
3. そろわなければ少し見せてから裏に戻す
4. すべてそろったら終わり

## モード
- ひとりで遊ぶ: 全部そろえたら「クリア！」
- オンラインで対戦: 別々の端末から同じ合言葉を入力した2人で交互にめくる。そろえたら続けてめくれ、
  そろわなければ手番交代。多くそろえた方の勝ち(同数はひきわけ)。
  取ったカードの枚数を画面下の左(あなた)・右(あいて)に、手番を真ん中に表示する

## 技術構成
- React + TypeScript + Vite + Tailwind CSS(タワーバトルと同じ構成)
- ルールは`src/lib/game.ts`の純粋な関数にまとめ、`src/hooks/useMemoryGame.ts`が裏に戻す待ち時間・経過時間などを受け持つ
- 画面は`BasePage`の4スロット(header / center / bottom / overlay)に、`pages/`の関数が中身を入れる方式
- 画像: `public/images/`(タワーバトルの写真を480pxに縮めたもの)。一覧は`src/lib/cardCatalog.ts`

## オンライン対戦
タワーバトルと同じ合言葉方式・同じFirebaseプロジェクト(Realtime Database)を使う。

- ホスト権威モデル: 先に合言葉を入力して待っていた側(ホスト=プレイヤー1)だけが盤面を持ってルールを進め、
  変わるたびに盤面をゲスト(プレイヤー2)へ配信する。ゲストは自分の手番にめくったカードをホストへ送り、届いた盤面を表示する。
- 部屋はタワーバトルと同じ`rooms/`配下に、`shinkei-room-…`という名前で作る。そのためデータベースのルールは
  タワーバトルのもの(`rooms/$roomId`の読み書きを許可)をそのまま使え、同じ合言葉でもタワーバトルの部屋とはぶつからない。
- ゲストの操作は一覧(`guestInputs`)に積み、ホストが届いた順に処理する(すばやく2枚めくっても取りこぼさないように)。
- 途中で抜けても同じ合言葉で入り直せば同じ役割のまま続きから再開する。決着後は2人とも「もう一度」を押すと次のゲームが始まる。
- 直近に使った合言葉(最大5件)は端末のlocalStorageに残り、ロビーでタップして選び直せる。

### セットアップ
`.env.example`を参考に、タワーバトルと同じFirebaseのconfigを`.env.local`へ書く
(Vercelにデプロイする場合はVercel側の環境変数にも同じ値を設定する)。
